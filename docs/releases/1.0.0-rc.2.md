# DevCade 1.0.0-rc.2

This release candidate adds optional usage tracking and fixes Maze Chase personal bests and global score submissions.

## Changes

- Completed Maze Chase games now save their personal best and submit it when global score sharing is enabled. Scores that were never saved by the old client cannot be recovered.
- Settings includes a separate, default-off usage-sharing option. When enabled, the client sends app-open and game-start/end events using a random installation identifier, without usernames or score credentials.
- A password-protected admin panel provides daily, weekly and monthly active installation counts, per-game sessions, and GitHub Release archive download counts. Downloads include repeat downloads and are not a count of unique players.
- The public website reads current leaderboard scores on opening and Refresh, retaining the newest valid snapshot if the service is unavailable.
- Deployment instructions cover the existing archive-based GCP installation and admin password changes.

## Install or update

No Go installation or source checkout is required. Download the archive for your OS and CPU and verify it against `SHA256SUMS`, or use Homebrew/Scoop once their manifests target this release.

```sh
brew update
brew upgrade cagridursun/devcade/devcade
devcade --version
```

```powershell
scoop update
scoop update devcade
devcade --version
```

The expected version is `devcade 1.0.0-rc.2`. Full instructions, including checksum-verifying installer scripts, are in the [installation guide](https://github.com/cagridursun/devcade/blob/main/docs/install.md). Existing profiles, preferences and personal bests are retained.

Usage sharing and global score sharing are separate options and remain opt-in. Updating the binary does not enable either option.

## Deployment and verification

The shared HTTPS score endpoint remains `https://devcade.cinesdigital.com`. The server/container must also be updated for website read CORS and admin analytics; installing a new client does not update the server.

The publishing workflow builds six self-contained archives, verifies checksums and installers, runs native race tests on Linux, macOS and Windows, and smoke-tests the leaderboard container before publishing the exact tested files.

An interactive terminal of at least 80 × 24 is required. Binaries remain unsigned and are not notarized. Windows/Linux ARM64 and Intel macOS are cross-built; interactive acceptance on every terminal and CPU is not claimed.
